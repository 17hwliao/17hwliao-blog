## 仍存在的问题与后续最小方案

### R12 · P1 · 依赖安全基线过旧

位置：[package.json](../package.json)、`pnpm-lock.yaml`。

现有 Next.js `16.0.10`、React／React DOM `19.2.1`。针对官方 npm registry 的生产依赖审计快照返回 `critical=8, high=65, moderate=49, low=17`；135 条 advisory 记录涉及 29 个包。计数包含依赖版本和打包／部署工具链，不能当作线上可利用漏洞数量。

[Next.js 官方 2026-10-14 公告](https://nextjs.org/blog/nextjs-security-update-october-14-2026) 提供 `16.4.1 / 15.5.28` 修复，并说明图像处理、Cache Components、Server Actions 各自的触发条件。本项目使用 App Router，但未发现 `use cache`、自定义 Server Action 或 Next Image 组件入口；这些公告的具体攻击前提不能全部认定已满足，也不能因为未使用某个入口就把过旧框架判为安全。jsrsasign 的 DSA 告警不等于本项目 RSA 签名链已被利用。Cloudflare 适配器及其依赖应与实际 Vercel 运行路径区分。

方案：先选满足公告修复的 Next 16 安全版本，核对 React/RSC、Node、SVG loader、React Compiler 和所保留 OpenNext 的兼容性，更新锁文件后做冻结安装、生产构建、服务端读取及 Markdown 回归。无需更换整个前端技术栈。本轮没有执行跨多个框架次版本的依赖迁移。

### R13 · P1 · 集合／站点配置仍会用过时草稿覆盖远程全量 JSON

位置：各 `push-projects / push-pictures / push-shares / push-bloggers / push-about / push-snippets / push-site-content` 服务。

非强制 ref 更新能阻止“读取父提交之后”发生的并发冲突，却不能发现“打开旧部署页面到按保存之间”远程已经发生的修改。服务通常从旧页面取整份列表，再以保存时最新提交为父节点写回，可能覆盖另一标签页／提交的新条目。文章归档的增量处理不能自动保护其他集合。

方案：所有编辑会话持有 `{baseRevision, original, draft}`，仓库适配器对每个目标文件做 expected blob SHA／内容哈希校验；以稳定 ID 应用新增、删除、修改，冲突时保留草稿。删除相册文件还必须检查引用。准备、删除、校验均固定同一提交；GitHub 请求需有有限等待，最终 ref 更新保持“已确认／未确认”区分。该项需要统一多个服务及编辑会话契约，本轮只完成文章链路和单页事务保护。

### R14 · P2 · 鉴权与编辑状态仍混合多种事实

位置：[auth.ts](../src/lib/auth.ts)、[use-auth.ts](../src/hooks/use-auth.ts)、[write-store](../src/app/write/stores/write-store.ts)、各列表页 persist。

令牌缓存只有字符串，没有过期时间／仓库与 App 身份。`hasAuth` 只检查缓存是否存在；过期后会先被视为可保存，再由 401 清除全部授权。GitHub 安装令牌会在一小时后过期，返回响应也包含过期时间，见 [GitHub 官方文档](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-an-installation-access-token-for-a-github-app)。

写作加载和提交共享 loading，写作、预览又有不同的全局 store；集合保存期间仍可发生新的编辑，完成回执可能用旧快照重置新草稿。新文章首次提交后也没有完整的规范化“已提交版本”回执。

方案：鉴权服务维护 scope、expiresAt 和单次刷新，权限失败不等同于私钥格式失败；编辑会话分别维护 load、draft、submit、confirmedVersion。提交按草稿 revision 更新基线，只合并本次已确认的版本，避免回执清空后续输入。浏览器 PEM 和可选缓存是现行兼容方式；前端公开密钥派生的 AES 加密不能隔离同源脚本，此处不宣称完成凭据隔离。长期方案见架构文档。

### R15 · P2 · 辅助工具与媒体生命周期有未闭环路径

位置：[image-toolbox](../src/app/image-toolbox/page.tsx)、[Live2DViewer](../src/app/live2d/live2d-viewer.tsx)、媒体选择及列表组件。

图片转换在异步完成时仍用数组 index 写结果，转换期间删除前项可能改变目标；批量失败后部分 converting 状态不一定释放。ImageBitmap 和部分替换／取消的 blob URL 没有完整回收。Live2D 的 CDN／模型初始化缺少卸载后失效判断，cleanup 可能早于异步创建 PIXI 对象。

方案：采用稳定媒体 ID 和任务 generation；每个转换 finally 释放自己持有的状态和 bitmap，失效结果立即回收；媒体预览 URL 归编辑会话所有。Live2D 的脚本加载缓存 Promise，失败可重试，卸载阻止后续挂载并销毁迟到实例。这些路径本轮仅静态核对，未执行真实图像批量转换或 WebGL 初始化。
