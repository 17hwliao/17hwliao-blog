## Review 范围与方法

按 light-code-review 的阶段工作流完成前置准备、调用链评审、专项检查、风险汇总、最小修复方案和问题二次核实，再按原问题清单定向复核。由当前多模态模型读取实际截图进行视觉判断，没有调用外部模型服务或操作用户桌面。

基线为本地 main / `2b0f5bb` 与已有未提交工作区。本阶段缺少独立提交边界，因此按已确认的展示文件与直接调用方界定范围，没有将全部 main 差异视为本轮改动。文章、鉴权修复、助手和其他已有工作区改动未纳入全量审计。

覆盖的实际路径：

- 项目列表 → ProjectRow → 展示数据 → 静态预览图与详情链接。
- 项目详情 → 受项目列表约束的本地 README / source 文件 → ProjectContribution 或 ProjectGallery → ProjectAdvantages。
- 优势证据链接 → hash 选择 → 图、说明、缩略图、弹层共用当前画面状态 → 关闭恢复与图片失败重试。
- PR 样例 → 原始报告 → 章节、判定、阻断状态与审计讲解；计时器、页面隐藏与离屏暂停的资源边界。
- 本地预览脚本 → 已有服务身份核对或隐藏进程 → 回执与自有进程停止边界。

专项判断：图片失败在模块内恢复，不移除优势或 README；静态查看没有业务提交或后台任务积压；切换图片与弹层共享状态，保留 Next 的 history state；报告缺证据不会显示为已测得收益。展示不读取私钥、不发起模型请求、不执行样例命令，README 仍沿用原有标签与 URL 白名单。没有新增业务存储迁移或权限契约。

视觉读取覆盖项目目录、PR 讲解、SQL 报告与优势、AgentMesh 优势、Zenix 工作画面与优势、TableCard 对局，以及 320px 浅/深色和 1440px 深色画面。390px 另做布局、主题色值与溢出检查。实际视口截图也核对了焦点与固定导航，避免以长元素取图的覆盖现象推断真实页面遮挡。
