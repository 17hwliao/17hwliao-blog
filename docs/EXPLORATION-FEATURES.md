# 探索与阅读功能

本地初版，2026-10-29。功能规格待实际使用后确定。

| 入口                       | 当前行为                                                                                                                                                                                          |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/knowledge`               | 根据公开文章的技术标签生成可点击主题图，支持主题内检索；四条阅读路线按学习顺序连接现有文章，读完状态来自阅读工作台。                                                                              |
| 页头搜索按钮、Ctrl/Cmd + K | 搜索公开文章元信息、项目、页面和音乐。支持上下键、Enter、Esc 与焦点返回，中文输入法组字期间不执行命令。                                                                                           |
| 公开文章详情               | 稍后读、当前位置与最远位置、主动标记读完、专注阅读、字号调整、选中文字保存摘录和想法。支持 CSS Highlight 的浏览器持续高亮已保存段落；其他浏览器可从摘录定位并选中原文。编辑器预览不创建阅读记录。 |
| `/reading`                 | 继续阅读、稍后读、摘录与想法、已读完；搜索、修改想法、删除和 JSON 导入/导出。                                                                                                                     |
| `/pictures/stories`        | 三本故事集引用原有八张照片与说明，逐章翻看、缩略图跳转、左右键翻页，点击后才请求共用音乐播放器。保留原 `/pictures` 层叠相册。                                                                     |

## 功能结构

```text
src/app/knowledge, reading, pictures/stories  薄页面入口
src/features/discovery  公开目录、关联、路线、命令面板
src/features/reading    记录模型、浏览器存储、正文工具、工作台
src/features/stories    故事编排、照片映射、章节界面
src/features/music      向现有播放器发送用户播放指令
src/styles/discovery.css  沿用站点 tokens 的响应式样式
```

公开文章元信息来自既有 `public/blogs/index.json`，项目来自既有项目列表，照片来自既有相册列表。隐藏文章不进入搜索、地图或路线。新增功能没有复制一份文章正文或引入第二个内容源；更新内容后随构建更新目录。

阅读路线位于 `src/features/discovery/catalog.ts`。故事标题、章节顺序与推荐心情位于 `src/features/stories/collections.json`；照片正文说明仍来自原相册。故事顺序是主题编排，不推断照片拍摄时间。

## 阅读数据与边界

全站检索使用 `Ctrl + K`（Mac 支持 `Command + K`），搜索文章元信息、项目与导航。文章内使用 `Ctrl + F`（Mac 支持 `Command + F`），仅检索当前正文与代码，显示匹配数量并高亮；`Enter` / `Shift + Enter` 或箭头按钮循环定位前后匹配，`Esc` 关闭并清除查找高亮。正文阅读工具中也有点击入口。查找不修改正文 DOM 或保存摘录，不跨文章记忆关键词；弹窗、编辑输入框和其他页面保留浏览器查找行为。不支持 CSS Highlight 的浏览器继续使用原生查找。

浏览器键 `17hwliao:reading:v1` 保存版本化记录，包括文章 slug、标题、最近位置、最远位置、书签、显式完成状态、摘录与想法。没有账号或跨设备同步；清理当前站点数据会删除记录。字号和专注模式仅作用于当前阅读页面。

仅打开文章不代表读完。滚动进度按正文视区比例记录，用户主动选择「标记为读完」才影响路线完成度。返回文章后需点击「接着上次的位置读」，不会强制跳转。

摘录保留原文字与文本偏移；定位时先验证原偏移，不匹配则搜索原文字。正文变化后找不到的摘录仍然保留并提示；相同文字多次出现且原偏移失效时会定位第一处，暂未实现内容版本迁移。

持续高亮使用 [CSS Custom Highlight API](https://developer.mozilla.org/en-US/docs/Web/API/CSS_Custom_Highlight_API)，按浏览器能力检测启用。现有 CSS 优化器不识别该伪元素，因此将固定样式规则放在阅读组件内，由浏览器解析；没有关闭构建检查或改变 Markdown 的安全边界。

同一页面使用共享存储通知，不同标签接收 storage 事件。写入前重新读取最新记录，保留其他文章已完成的写入，进度不会倒退；不同标签同时改同篇记录尚无跨标签事务锁，不承诺强一致。

存储被禁用、配额不足或旧数据损坏时显示未保存/不可读取信息，不以空数据覆盖原存储。导出可备份原始数据；导入先校验，再明确确认替换，限制 5 MB。重置和删除有确认。

音乐由 `HeaderMusic` 统一持有唯一 audio。命令、队列与故事按钮只在用户动作后发出请求，由原播放器负责成功、加载、暂停与失败反馈；导航和翻页不自动播放。

## 游客阅读与外观

页头的太阳 / 月亮入口提供浅色、深色、跟随系统三个选项。偏好保存到 `17hwliao:appearance:v1`，首屏脚本在内容绘制前读取；系统模式响应设备配色变化，同源标签页通过 storage 事件同步。存储被禁用时仍可切换当前页面，并说明偏好未保存。主题不写回作者的网站配置，不涉及 GitHub。

暖白和炭灰配色由共用变量控制。首页与关于页加入轻微纸张纹理，正文保持平整背景。代码同时生成浅色 / 深色语法配色；弹窗、提示、高亮、表单与目录沿用主题。图片与品牌素材保留原色，棋盘的黑白棋子保持语义颜色。

首页「初次来，从这里开始」连接三篇精选文章、一条 Go 路线和两个代表项目，选文说明单独编排，原文保持不变。有可用的未完成阅读记录时显示「继续阅读」；该按钮显式携带 `resume=1` 恢复记录的位置。普通文章链接仍从文章开头进入。恢复会等待正文图片加载，最长等待 2.5 秒；加载极慢或正文变化时，历史百分比不保证对应同一句文字。损坏 / 不可读取的记录会提示进入工作台处理，不覆盖原数据。

正文工具栏保留收藏、目录、查找、设置。目录覆盖一级至六级标题及列表 / 引用中的标题，重复标题生成独立地址；章节点击会设置滚动位置和焦点。阅读设置集中字号、专注模式、显示主题和工作台入口。字号与专注模式仍只作用于当前文章。文末连接所属路线的下一篇 / 路线终点，并保留相关文章。

手机上工具栏固定于底部，留出安全区和正文底部空间；目录、阅读设置和主导航使用底部抽屉，关闭按钮在滚动时保持可见。站点搜索、正文查找都保留点击入口。代码块和宽表格在自身容器滚动，复制按钮提供 44px 触摸范围。图片支持键盘和点击打开、100%–300% 放大、滑动查看、恢复适屏、失败重试、Esc / 关闭按钮退出，并恢复原焦点和阅读位置。视窗变量跟随 VisualViewport 变化，让短视窗下的面板仍有可滚动空间。

本地隔离浏览器定向覆盖 320 / 390 / 768 / 1024 / 1440px、触屏点击、360px 短视窗、主题保存 / 跨标签 / 系统切换、继续阅读、目录定位、图片放大与失败恢复，以及 Ctrl+K / Ctrl+F。未连接真实手机设备；触屏与短视窗模拟不代表所有手机浏览器或真实软键盘均已验收。没有执行推送、部署或 AI Review。

## 已有检查

`node --test tests/*.test.cjs` 包括 4 组探索功能测试、3 组游客阅读 / 主题测试、5 组文章展示测试和 16 组 Review 回归测试。检查覆盖目录/路线、损坏与配额失败存储、故事照片与说明映射、主题首屏初始化、完整目录、代码语言栏与文章标题一致性，以及导入 README 表格的正确结构。

另有本地隔离浏览器自动化覆盖命令键盘和焦点、摘录保存/恢复、本地音频、故事翻页、390px 布局。自动化使用独立浏览器上下文，不读取私钥、不写 GitHub，也不改文章或照片。

这是一版本地交互实现，测试不代表用户已确认最终规格。
